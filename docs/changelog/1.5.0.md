# 1.5.0 — Binary compatibility

Planned release, based on published tag `1.4.4`.

- Restore `Oak.tag`, `quiet`, `maxLogLength`, and `maxTagLength`, with covariant JVM bridges
  preserving the old `Oak` return descriptors and the current facade return descriptors.
- Restore the protected option getters and their consume-on-read/subclass override contract.
- Keep direct destination tags one-shot and return the destination without allocating a facade.
- Validate public ABI with Kotlin's built-in validator and execute separately compiled consumers
  of published 1.1.0 and 1.4.4 against candidate JVM and Android Maven publications.
- Reproduce the 1.1.0 consumer's `NoSuchMethodError` on published 1.4.4 as a negative control.
- Omit ABI configuration only in the isolated older CodeQL analysis build, preserving strict
  ABI validation in the normal release build without rewriting build scripts.
- Move compatibility validation to a configurable `arch-compatibility` convention plugin and
  aggregate it through `ciCompatibility`, included by `ciCoverage`.

See [binary compatibility](../binary-compatibility.md) for verified contracts and target limitations.
